## 1. Brand Kit 定义

这份 Kit 不是一套“春节红金风格”，也不假定存在一枚名为“抖音春节”的新母 Logo。它是一个跨节目节点的品牌应用事实源，负责回答：

1. 当前成品属于春晚还是元宵，节目主标题应使用哪一套正式锁定；
2. 总台节目、抖音平台、火山引擎与豆包等主体如何组合，谁是主身份、谁是合作署名；
3. 页面、直播频道、站内资源位和行政传播如何选择受控变体；
4. 哪些元素允许配置，哪些关系必须固定，发布前如何校验；
5. 每项规则来自哪个 Figma page、node 与正式尺寸。

Brand Kit 面向设计师、生成 Agent 和发布校验服务共同消费。它输出身份规则、Token、组件契约、Golden Evidence 与 Reject 边界，不替代页面模板、Style Bible、IP Kit 或项目素材库。

## 2. 边界与资产归属

| 内容 | 归属 | 是否进入本 Kit |
| --- | --- | --- |
| 春晚 / 元宵节目标题锁定 | 节目节点身份 | 是 |
| 抖音 Logo、平台传播署名 | 平台身份 | 是 |
| 火山引擎、豆包合作方锁定 | 合作身份 | 是，仅限正式合作口径 |
| 直播频道名与状态结构 | 频道组件 | 是 |
| 红金纹样、山水、烟花、光效 | Style / 项目视觉 | 否，只作为应用证据出现 |
| 马年角色、人物、节目画面 | IP / 项目素材 | 否 |
| 页面模块、路由、榜单和互动逻辑 | 页面 / 玩法资产 | 否 |
| Figma“过程”页与试稿 | Reject / 过程证据 | 否 |

关键结论：春晚和元宵属于同一个春节传播资产族，但它们不是同一个视觉皮肤的两段文案。可共享的是平台级规则和治理方式，不可共享的是节目标题锁定、节目日期、合作口径与节点应用视觉。

## 4. 身份架构

### 4.1 PROGRAM — 节目节点主身份

职责：回答“这是谁的节目、当前是哪一个春节节点”。

- 春晚：使用“2026 中央广播电视总台春节联欢晚会”正式节目标题锁定；
- 元宵：使用“2026 总台元宵晚会”独立节目标题和节点日期；
- 不得用系统字体重排节目名，不得只替换“春晚/元宵”文字制造变体；
- 节目标题始终高于频道名、平台动作和辅助说明。

### 4.2 PARTNER — 官方合作方锁定

职责：表达节目主体与技术/产品合作关系。

春晚正式成稿可确认以下横向关系：

`总台春晚标题 → 菱形分隔 → 火山引擎 → 菱形分隔 → 豆包`

固定项：

- 主体顺序；
- Logo 原形、视觉基线和相对比例；
- 菱形分隔与独立安全区；
- 只在合作口径已确认的节目节点使用。

可配置项：

- 来源已提供的横向、居中或窄版变体；
- 在红底、浅底或图像底上的已核验反色版本；
- 整体尺度与 Surface 位置。

### 4.3 CHANNEL — 抖音传播署名

职责：回答“用户在哪里看、下一步做什么”。

- 抖音 Logo 与“上抖音 看春晚”等传播口号属于平台层；
- 直播频道名、节目时间、观看状态和按钮属于渠道层；
- 平台署名不能覆盖节目标题，也不能与合作方链拼成一枚新 Logo；
- 元宵必须读取元宵节点自己的传播口号、节目日期和合作信息。

## 6. 字体与文字角色

当前 Figma 足以确认排版角色和视觉处理，但不足以可靠声明具体字体家族与授权。以下规则在字体清单归档前只定义职责，不伪造字体名。

### 6.1 节目主标题字

- 春晚使用总台正式节目标题锁定，可见金色线性和立体版本；
- 元宵使用独立节目标题件；
- 用于节目封面、直播主机位、资源位、页面 Hero 与行政屏；
- 待归档：SVG/可编辑矢量、反白版、最小尺寸和安全区。

### 6.2 平台传播口号

- 高字重中文展示字；
- 春晚行政屏中的“上抖音 看春晚”采用金色立体处理；
- 口号必须低于节目标题或官方合作链，不得伪装成节目 Logo；
- 横竖版可以换行，但不可改写核心语义。

### 6.3 合作方字标

- 火山引擎与豆包必须使用正式 Logo/字标；
- 不得用系统字体代写，不得重绘；
- 在窄资源位中优先使用来源已提供的精简锁定，而不是任意缩小完整组合。

### 6.4 直播频道标题

- 使用清晰的无衬线标题角色；
- 主机位、竖屏、年年有你、字幕与手语以频道名区分；
- 不复刻节目主标题的立体金字效果，避免身份层级竞争。

### 6.5 UI 正文与数据

- 常规中文无衬线；
- 日期、直播时间、状态和按钮按信息优先级分配字重；
- 正文、时间和状态不可烘焙进 Brand Kit 位图，应保留结构化字段。

## 7. 规范组件

### 7.1 春晚节目签名

- Anatomy：年份 / 总台节目归属 / 春节联欢晚会标题 / 节目图形标；
- Fixed：字形、图形、年份关系和节目名称；
- Configurable：来源提供的横竖、金色或反白版本；
- Evidence：主机位、节目封面、活动 Banner、行政屏。

### 7.2 元宵节目签名

- Anatomy：年份 / 总台元宵晚会标题 / 节目日期 / 元宵资源位视觉；
- Fixed：节目名、日期和元宵节点身份；
- Configurable：横版、竖版、方图、直播封面等来源变体；
- Evidence：总板 `750:117489`，横版关键节点 `750:117493`；
- Status：独立导出与透明标题源待归档。

### 7.3 官方合作方锁定

- Anatomy：节目标题 / 分隔 / 火山引擎 / 分隔 / 豆包；
- Fixed：次序、原形、比例、基线和安全区；
- Configurable：来源提供的版式与反色；
- Evidence：活动 Banner、活动头图、节目封面、行政横屏。

### 7.4 抖音传播署名

- Anatomy：抖音 Logo / 传播口号 / 节目时间 / 主行动；
- Fixed：Logo 原形、节目与平台的主从关系、关键时间口径；
- Configurable：口号版本、横竖排和 Surface 位置；
- Evidence：主会场、行政屏、元宵资源位。

### 7.5 直播频道封面头

- Anatomy：节目签名 / 频道名称 / 直播状态 / 背景框架；
- Fixed：节目签名安全区、频道可读性、直播状态位置；
- Configurable：主机位、竖屏、主题、字幕、手语频道与画面；
- Evidence：春晚直播间物料 6 个正式节点；元宵直播状态 3 个正式画面。

### 7.6 跨画幅传播框架

- Anatomy：节目/合作方锁定 / 主口号 / 节目时间 / 平台署名 / 安全区；
- Fixed：身份件完整、Logo 不贴边、合作方次序不变；
- Configurable：横/竖/方画幅、主口号、渠道说明和背景密度；
- Evidence：节目封面、活动资源位、行政屏与元宵资源位总板。

## 8. Surface 选择矩阵

| Surface | 必须保留 | 可配置 | 禁止 |
| --- | --- | --- | --- |
| 页面 Hero | 节目标题、抖音传播署名、节目时间 | 主视觉、行动入口、内容模块 | 用频道名取代节目标题 |
| 直播主机位 | 节目签名、频道名、直播状态 | 频道画面、横竖版 | 不同频道共用错误标题 |
| 字幕 / 手语频道 | 节目签名、频道辅助信息 | 背景与节目画面 | 牺牲字幕或手语识别区 |
| 节目封面 | 节目标题、合作方链 | 横/竖/方版与画面 | 机械裁切完整横版 |
| 窄 Banner | 最小节目签名、合作方精简锁定 | 单一利益点、背景密度 | 同时塞入多个口号和人物 |
| 行政横/竖屏 | 节目/合作方锁定、传播口号、抖音署名 | 场地说明、横竖版 | 把内部说明并入 Logo |

## 9. 发布前校验

必须检查：

1. `event_branch` 已明确为 `spring_gala` 或 `lantern_festival`；
2. 节目标题、日期、合作口径与分支一致；
3. 总台节目标题、抖音、火山引擎和豆包 Logo 未被拉伸、描边、重绘或 AI 仿画；
4. 合作方顺序、分隔关系和安全区未改变；
5. 直播频道名、字幕/手语状态可读；
6. 图片尺寸与 Figma source node 一致；
7. 所有外发成品记录 page、node ID、原尺寸和 Kit 版本；
8. “过程”页、试稿和无来源图片未进入 Golden Reference。
