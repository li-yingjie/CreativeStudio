# 限时找物闯关玩法包

> 能力 ID：`gameplay.hidden-object.magpie-hunt@0.7.0`  
> 预设：`qixi-magpie-bridge-2026`  
> 成熟度：需求已验证；Runtime、任务、风控和奖励接口待归档。

## 1. 这是什么

这是从《七夕「搭建鹊桥」互动玩法》提炼的可复用“限时找物 / 找茬闯关”能力。可复用能力只定义对局、关卡、次数、任务、奖励、异常与事件契约；“七夕、喜鹊、鹊桥、券包”等活动叙事保存在预设中，不写死进核心 Runtime。

适合：大规模泛用户、30–120 秒轻互动、多场景渐进难度、需要签到/分享回流和阶段奖励的活动。  
不适合：实时多人竞技、没有可校验热区的场景图、奖励/风险/任务服务尚未接入的项目。

## 2. 玩家主循环

1. 首访进入活动，领取 1 次挑战机会。
2. 进入当前关卡即消耗 1 次；资源加载完成后 3-2-1 开始计时。
3. 正确点击累计目标；错误点击展示红色 X 1 秒，不额外扣时。
4. 找齐目标即成功；超时、确认退出或杀进程视为失败，次数不返还。
5. 每关成功发 1 次抽奖机会；第 3、7 关额外发消费券。
6. 次数不足时通过签到或好友助力获取；全通后任务切换为邀请好友访问得抽奖机会。

## 4. 必需输入

- `sceneAssetRefs`：每关 1 张已授权场景图。
- `hotspotManifest`：目标 ID、归一化坐标、命中半径和安全区；数量必须与每关目标数一致。
- `attemptPolicy`：初始、消耗、发放、日重置与幂等规则。
- `rewardPolicyRef`：抽奖机会和第 3/7 关奖励的真实服务引用。
- `riskPolicyRef`：参与、助力和发奖前的风险判断。

任何必需引用缺失时，Agent 只能生成“待接入”配置，不得宣称玩法可发布。

## 5. 输出与事件

输出：`attempt_ledger`、`level_progress`、`reward_receipt`、`activity_ledger`。  
核心事件：`level.started`、`target.found`、`target.missed`、`level.completed`、`level.failed`、`attempt.granted`、`reward.granted`、`share.returned`。

所有入口必须携带渠道标识；任务邀请回流和普通分享回流必须分开。逐关上报曝光、开始、成功、失败、退出和用户级耗时。

## 6. 状态与兜底

- 加载超过 300ms：展示加载态，计时不开始。
- 剩余 10 秒：时钟抖动、倒计时变红闪烁。
- 风控或资格异常：只保留活动标题和“活动太火爆了，请稍后再试”，隐藏任务、奖励、奖品和榜单。
- 回到首页的动画优先级：关卡进度 → 里程碑奖励 → 主会场动效；若只有好友助力，只展示助力反馈。
- 重新进入活动：首页状态直接刷新，不补播喜鹊飞行和进度动画。

## 7. 发布验收

- 7 关热点数分别为 5/6/6/7/7/8/8，逐关合计 47，且不越过安全区；源文档另标 49，口径未确认前阻断发布。
- 首次引导每个 uid 在活动期只展示一次。
- 第 3、7 关奖励和每关抽奖机会均幂等，必须返回 receipt。
- 通关前助力与全通后邀请为两套独立日额度，每日 00:00 重置。
- 奖励失败不得渲染为到账；风险状态不得暴露任何利益模块。
