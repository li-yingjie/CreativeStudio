# 输入合同：需求文档、Figma 与混合输入

## 先判断输入扮演什么角色

同一个 Figma 链接可能是最终标准，也可能只是质量参考；需求文档里的 Demo 可能是产品逻辑草图，也可能是已批准视觉。不要按文件类型猜权威性。根据用户当前指令、来源状态和内容完整度，为每个输入标注：

- `sourceOfTruth`：必须还原的事实或设计；
- `constraint`：必须遵守但不需要照抄的边界；
- `reference`：只用于启发或校准质量；
- `example`：说明意图的粗略示意；
- `unknown`：权威性不清，只有在会实质改变产物时才询问。

冲突优先级不是永远“Figma 高于文档”。使用：用户当前明确指令 > 已批准且仍有效的来源 > 明确需求事实 > 参考图/粗 Demo > Agent 推断。发现已批准来源互相冲突时，只问影响最终结果的那个冲突。

## 再按语义槽位登记像素证据

项目级输入模式只能决定总体策略，不能替代素材槽位的来源登记。同一个页面中，平台 Logo 可能是可直接使用的 A 级证据，粗 Demo 的模块截图是只可信意图的 B 级证据，未提供的奖励图则是需要原创生成的 C 级证据。逐槽位记录证据等级、来源定位、授权范围和置信度，具体判据见 `pixel-provenance.md`。

## 模式 A：需求主导生成

适用：需求文档描述目标、玩法、内容和约束；内嵌画板或截图只是一张粗 Demo，没有精确视觉和完整状态。

### 提取

- 从文字、表格和 Demo 中提取用户任务、核心循环、必需模块、内容规模、状态和业务约束。
- 把粗 Demo 当作信息架构或产品意图证据，不把它的临时配色、间距、占位图和低保真排版当作视觉规范。
- 识别 Demo 没画出的长列表、异常态、交互反馈、奖励、分享回流和终端状态。

### 生成

1. 对尚未明确的边界和玩法执行确认。
2. 调度组件库，生成页面蓝图和可运行灰模。
3. 以文档的品牌要求、平台规范和质量参考生成三套 Brand Kit 联合样张。
4. 选择后生成完整素材 BOM 与正式素材。
5. 编译成分层可编辑页面并进行审查循环。

### 验收

验收重点是需求覆盖、核心循环、内容规模、素材完整度、视觉统一和可编辑性，而不是像素级复刻粗 Demo。

## 模式 B：Figma 主导实现

适用：用户明确要求还原、复刻或实现某个已批准 Figma 节点，且 Figma 提供足够完整的页面、组件、素材和状态。

### 提取

- 读取目标 Frame 及其相关组件、实例、variant、样式、变量、素材、原型交互和相邻状态，不只看单张截图。
- 建立 Figma 节点到页面语义、组件、素材槽位和运行时状态的映射。
- 区分可直接导出的复杂视觉、必须用代码承载的动态内容，以及需要重新生成或补齐的缺失素材。
- 提炼该文件实际使用的 Brand Kit；不要另造三套视觉方向，除非用户明确要求探索新方向。

### 生成

1. 已由 Figma 明确的边界、玩法或 Brand Kit 直接写入决策日志并标明来源，不进行假确认。
2. 优先复用兼容的组件行为；为 Figma 视觉绑定 Brand Kit 和素材槽位。
3. 对 Figma 中复杂装饰区使用受边界约束的导出/矢量/图像资产，对动态文字和状态使用 DOM/code。
4. Figma 未覆盖但运行所需的状态，按现有视觉语法补齐并标记为 Agent 推断。

### 验收

- 对所有必需 Frame 和关键 variant 做区域级对比，而不是只比首屏。
- 检查几何、字体、图层、裁切、密度、色彩角色、深度、固定/吸顶、滚动和状态切换。
- 同时满足运行时、响应式和组件可编辑要求；不能为了像素相似把整页扁平化。

## 模式 C：混合输入 / Figma 仅作质量参考

适用：需求文档定义新活动，另有 Figma 或线上活动用来表达“希望达到这种复杂度和质感”，但不允许复制其 IP 或具体页面。

### 提取

- 从需求文档获取产品事实和内容。
- 从参考 Figma 提炼设计方法：密度、景深、装饰层级、艺术字处理、组件材质、按钮质感、段落节奏和交互反馈。
- 明确禁止复制的活动标题、角色、插画、文案、奖励、专属配色和受保护素材。

### 生成

1. 以新需求完成边界和玩法。
2. 用参考 Figma 的质量方法、平台规范和新内容生成独立 Brand Kit 联合样张。
3. 生成新的素材，而不是把参考 Figma 的素材搬进项目。
4. 组件行为可复用，视觉必须由新 Brand Kit 和新素材重新绑定。

### 验收

不做逐像素一致性承诺；按语义区域比较复杂度、视觉焦点、信息密度、深度、按钮区分度、页面节奏和完成度，同时检查独立性。

## 模式 D：只有截图或不可读取链接

- 明确记录证据缺失，不声称已经读取文件结构。
- 截图可用于可见区域的构图、颜色和密度分析，不能证明隐藏状态、完整页面长度、组件边界和交互。
- 先尝试获得可读的 Figma/文档权限或结构化导出；无法获得时按“混合参考”处理，并把不可验证部分列为限制。

## 防止两种常见失败

### 把需求文档平铺成网页

文档章节不是页面信息架构。必须先还原用户循环、页面状态、内容规模和终端目标，再生成蓝图。

### 把 Figma 当整图贴进页面

视觉还原不等于整页截图。必须重建语义组件和交互，保留独立编辑槽位，只把复杂美术区域作为受控图像/矢量资产。
