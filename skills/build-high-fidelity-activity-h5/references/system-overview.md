# 高保真活动 H5 生成体系总览

## 一句话介绍

`build-high-fidelity-activity-h5` 是生产编排 Skill：它约束 Agent 如何判断输入证据、在什么时候理解需求、向用户确认什么、如何调度玩法组件、何时生成素材、怎样组装可编辑页面，以及什么质量门禁通过后才能交付。它本身不是某个活动模板，也不单独提供抖音视觉。

## 到底靠什么生成

| 能力层 | 负责什么 | 不负责什么 | 主要产物 |
| --- | --- | --- | --- |
| 流程 Skill | 三次人机决策、阶段顺序、产物时机、素材 BOM、审查和交付门禁 | 不定义某个活动的具体视觉和玩法文案 | 决策日志、页面蓝图、生产计划、QA 证据 |
| Brand Kit Skill/配置 | 抖音或某活动的视觉语法：色彩角色、字体、形状、材质、景深、图标、动效和生图提示词 | 不负责业务状态机和页面流程 | 三套联合样张、设计 token、提示词、视觉规范 |
| 玩法组件库 | 可复用的行为与状态机，如投票、收集、协作进度、任务、排行、奖励、分享回流 | 不写死活动专属 IP、素材和配色 | 组件实例、状态契约、编辑槽位、数据接口契约 |
| 素材生成能力 | 按 BOM 生成 KV、艺术字、角色、奖励、场景和装饰，并完成透明度、尺寸和一致性检查 | 不决定用户流程，也不把整页生成成一张图 | 经过验收并绑定槽位的正式素材 |
| 页面编译器/编辑器 | 将蓝图、组件、Brand Kit 和素材编译成可运行页面；支持分层选择和局部编辑 | 不替代产品决策和视觉审查 | 可运行灰模、高保真 H5、组件树、CompileRun |
| 审查器 | 用运行时、视觉、响应式、交互和可编辑门禁对抗式检查并触发修复 | 不用“测试通过”替代肉眼与截图检查 | 门禁报告、修复记录、最终预览 |

当前本地已经落地两个可直接调用的知识源：`$douyin-acg-event-brand` 提供 `brand.douyin-acg-event-experience@1.0.0`，`$activity-h5-component-library` 提供 `knowledge.activity-h5-components@1.0.0`。前者是视觉合同，后者是行为合同，流程 Skill 负责编排二者。

因此，最终页面不是“靠一个 Prompt 生成”，而是：

`权威输入 + 尚未解决的产品决策 + 页面蓝图 + 玩法组件实例 + Brand Kit + 完整素材 BOM + 编译器 + 审查循环`。

权威输入可以是需求文档，也可以是要求精确实现的 Figma；两者使用不同的生成合同，详见 `input-contracts.md`。

## 主流程与系统职责

| 阶段 | 用户看到什么 | Agent 静默完成什么 | 使用的核心能力 | 持久产物/界面变化 |
| --- | --- | --- | --- | --- |
| 1. 原始输入（人） | 用户输入“根据文档生成活动页：七夕「搭建鹊桥」互动玩法” | 读取原始文档及内嵌内容；区分事实、推断、待确认；持久保留原文；生成页面需求初稿；不把内部分析刷到对话 | 文档读取 + 流程 Skill | 原始文档、页面需求初稿进入“文档” |
| 2. 定边界（人 + Agent） | 一张边界确认卡：当前理解、核心问题、三个互斥预设、其他输入、推荐项和理由 | 把选择追加到需求文档，不覆盖历史；暂不生成正式页面 | 流程 Skill 的第一次决策门 | 页面需求文档追加版本/确认记录 |
| 3. 定玩法主线（人 + Agent） | 三套真正不同的玩法卡；每套展示核心循环、每日动作、奖励解锁和主要组件 | 用边界约束生成候选；确认后更新活动方案并创建玩法配置 | 流程 Skill + 玩法建模 + 组件库能力检索 | “玩法配置”产物创建；回放中此时才出现玩法 Tab |
| 4. 页面蓝图与可运行灰模（Agent） | 不增加用户确认；用户可在页面产物查看和试玩灰模 | 自动完成信息架构、用户动线、组件树、页面状态、基础交互、组件调度和初步试玩修复 | 页面蓝图 + 组件库调度 + 编译器 | “页面”下创建按组件拆分的可运行灰模 |
| 5. 定 Brand Kit（人 + Agent） | 视觉未定时展示三套使用同一真实槽位的最小联合样张：主 KV、艺术字、代表性玩法组件、主按钮、卡片/背景材质、色板/字体层级；若已批准 Figma 是视觉真源，则展示提炼结果而非重新选风格 | 未定方向时只生成联合样张，不批量生产全部素材；Figma 主导时抽取现有 Brand Kit 和资产/组件合同 | 流程 Skill 的第三类决策 + Brand Kit 提炼/生成 | 回放中素材库 Tab 出现并自动切入；选择或抽取后锁定 Brand Kit 版本及来源 |
| 6. 页面生产、审查与交付（Agent 循环） | 最终只收到一条交付总结，右侧自动切到“预览” | 生成完整素材 BOM 和正式素材；绑定组件；完成高保真页面；循环执行视觉、交互、响应式、编辑能力检查与修复 | Brand Kit + 生图/素材管线 + 组件库 + 编译器 + 审查器 | 高保真页面、资产清单、QA 报告、完整 CompileRun 回放 |

## Skill 约束了什么

### 人机边界

- 最多只让用户决定边界、玩法主线和 Brand Kit 三类事情；输入中已经明确的内容直接记录来源并跳过确认。
- 灰模、素材 BOM、组件拆分、修复和审查由 Agent 负责。
- 确认信息追加保存，不覆盖历史；对话只展示用户做决定所需的信息。

### 生产顺序

- 玩法确认前不创建玩法 Tab，也不正式生成页面。
- 玩法确认后先做可运行灰模，再做视觉风格。
- Brand Kit 选择前只生成三套可比联合样张；选择后才批量生产正式素材。
- 门禁未通过不得进入最终交付。

### 页面质量

- 页面必须有完整素材 BOM，不能只有背景图。
- 复杂品牌视觉交给图片/矢量，动态状态和交互保留在代码中。
- 主要组件必须可以单独选中和编辑，不能整页扁平化。
- 不允许占位、横向溢出、低对比文字、状态切换导致外层几何跳变或假按钮。

### 可复用性

- 流程方法进入 Skill。
- 活动视觉进入 Brand Kit。
- 稳定行为进入组件库。
- 项目具体素材进入素材库。
- 某一活动的标题、IP、配色和文案不得污染通用能力。

## 交付门禁

以下条件必须全部通过：

1. 核心素材无占位且全部绑定到语义槽位。
2. 页面无横向溢出，完整预览可滚动。
3. 文字和关键操作对比度经过截图审查。
4. 会场、章节、Tab 和状态切换不改变外层几何。
5. 主要玩法用本地 mock 状态也可以完整运行。
6. 关键模块可以单独选择和编辑。
7. 页面完整度达到活动终端用户可用水平。
8. CompileRun 保存从原始输入到交付的全部阶段并可回放。
