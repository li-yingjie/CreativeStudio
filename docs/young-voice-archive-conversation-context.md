## 1. 业务目标

为唱歌主播制作移动端运营 H5「Young 声音藏品计划」。

- 活动周期：8 月 28 日至 9 月 1 日。

## 2. 过程与关键反馈

### 阶段一：官网式 H5 与通用卡片

最初页面采用规则的章节标题、统一圆角卡片、后台式字段和进度组件。

用户反馈：页面过于像官网 H5，缺少运营长图的排版节奏；礼物卡片结构与 benchmark 缺乏相似性。

结论：不能只换颜色和字体，必须调整信息构图、素材关系和模块节奏。

### 阶段二：参考「文物青年盘活企划」

曾以米白纸张、蓝色手绘边框、黄色荧光笔、文物图片和不规则说明纸为视觉母版，尝试了：

- CSS/SVG 手绘纸张底板。
- 图生图背景加 HTML 文字定位。
- 模块底图与绝对定位文案。
- 将底图改造成可伸缩容器。
- 将部分模块重构为普通代码组件。

暴露的问题：

1. 生成底图和 HTML 文字的安全区没有统一坐标规范，导致标题、正文、数字经常漂移或重叠。
2. 背景图片被拉伸时，视觉锚点随容器变形，文字位置仍然失准。
3. 图片内部已经带有构图，但 DOM 又建立一套独立排版，两套系统互相冲突。
4. 重复使用花朵、胶带、麦克风和手绘线条，导致画面杂乱。
5. 三件礼物曾被处理成步骤，错误表达了递进关系。
6. 字体只做了字体包替换，没有建立标题、正文、英文、数字各自的字形职责。

工程结论：底图只适合承担纯视觉氛围或固定素材；业务文案、数字、任务状态和按钮必须由自身组件管理尺寸与排版。不能在含有完整卡片构图的图片上再次覆盖一套自由流动文字。

### 阶段三：新音乐企划 benchmark

用户否定「文物青年」作为最终视觉母版，改用「陶喆的音乐客厅 / Soul Power」深夜音乐企划长图。

第一次反推虽然识别了深蓝、黄色与音乐房间，但执行仍有四个明显错误：

1. benchmark 是二维动漫/插画风，生成的第一版 KV 却偏写实、三次元。
2. benchmark 的内容模块是便利贴、胶带、票根和照片纸拼合，第一版仍沿用了旧 HTML 卡片结构。
3. 字体描述过于粗略，实际落地仍以基础苹方为主。
4. 描述的模块语言与最终生成页面不一致。

用户明确要求：放弃此前页面，不要继续修改旧 HTML；按新思路重新生成独立页面。

## 3. 当前确认的 benchmark 规则

### 头图

- 二维动漫背景插画，不是照片、写实渲染或 3D。
- 深夜房间、城市窗景、吉他、唱片机、笔记本和麦克风构成音乐生活场景。
- 使用平涂、明确轮廓、简化透视、蓝色柔光和少量颗粒质感。
- 主标题集中在画面中上部，周围素材为标题让出安全区。
- 头图只建立活动情绪和主题，不承载复杂规则卡片。

### 页面结构

- 全页保持深蓝连续底色，不按官网区块做规则切割。
- 阅读顺序：情绪 KV → 活动说明与日期 → 礼物收集 → 唱歌浓度任务 → 我的声音档案 → 派对资格。
- 模块宽度、角度和位置允许变化，但始终服从单一纵向阅读线。
- 模块使用便利贴、倾斜纸条、胶带、票根、照片纸和局部涂鸦拼合。
- 黄色只承担任务、奖励、进度和 CTA 强调；浅蓝承担辅助标签和连接信息。
- 装饰必须服务内容，不应在每个模块重复堆叠相同物件。

### 字体系统

不能再用“一套苹方覆盖全部内容”。当前页面将字体角色拆开：

1. 主 KV 中文：`HanziPen SC / Hannotate SC / Kaiti SC / STKaiti`，形成不等宽、带手写感的标题。
2. 模块标题：`Heiti SC / STHeiti / Microsoft YaHei`，使用高字重、紧字距、黄色下划线与深蓝投影。
3. 正文：`Hiragino Sans GB / Heiti SC / STHeiti`，中等字重、短行宽、较大行距。
4. 英文标签与数字：`Arial Narrow / Roboto Condensed / Impact`，使用窄体、大写和拉开的字距。
5. CTA：粗黑体，置于黄色胶囊或便利贴形状中，不采用通用官网按钮。

项目当前没有独立中文字体文件，因此使用系统中文字形组合，并通过字重、字距、旋转、描边、投影和纸条背景建立 benchmark 的字体动作。如果后续提供正式授权字体，应分别替换对应角色，而不是全局替换。

## 8. 后续继续工作的判断标准

后续任何修改都应先回答：

1. 是否仍然是二维动漫音乐企划，而不是写实或文物手账？
2. 模块是否像贴在长图上的便利贴/纸条，而不是产品 UI 卡片？
3. 标题、正文、英文、数字是否仍有清晰的字体角色差异？
4. 图片是否只承担氛围或物件，业务文字是否由组件自身排版？
5. 三件礼物是否保持同权平行？
6. 黄色是否只用于关键强调，而没有扩散成大面积噪音？
7. 模块之间是否在同一深蓝世界中连续过渡？

如果以上任一项不成立，应优先修正结构或视觉系统，而不是追加装饰。

## 10. 2026-09-07 固化的复刻方法

### 10.1 先反推视觉行为，不先找组件名

有效路径来自 Obsidian DesignSystem 研究与模块母板实验：先把参考图拆为画面职责、表面材质、文字形态、内容安全区、层叠关系和细节语法，再映射业务内容。不能看到“卡片”就直接调用通用 Card，也不能只记录“深蓝、黄色、粗体”。

反推时必须记录可执行的形态参数：

- 纸面是规则矩形、折纸还是撕边；是否有折面、硬折线、错位阴影和颗粒。
- 标题的宽窄、重心、倾斜方向、字号差、基线关系和高亮方式。
- 主标题、副标题、正文标签分别从哪条轴开始，以及它们是否刻意错位。
- 模块之间谁压谁、压多少、被压模块的文字安全区从哪里开始。
- 括号、纸飞机、胶带和外伸框线出现在哪类信息旁边，承担什么引导作用。

### 10.2 图片、SVG 与 HTML 的职责边界

- 主 KV 属于不可拆的情绪画面：二次元房间、光线、物件和手写活动字标可以由图生图共同完成，避免 HTML 字体与插画字形割裂。
- 业务规则、日期、任务、礼物数量、状态和按钮必须使用语义化 HTML，保证文字可改、容器可撑高。
- 折纸轮廓、撕边、折面和错位描边使用可缩放 SVG/CSS，HTML 文字只进入事先定义的安全区。
- 不能把一张已经包含完整信息构图的底图拉伸后，再用绝对定位覆盖第二套文字系统。

### 10.3 字体反推采用 Morphology Contract

字体还原不能止于“用了哪款字体”，而要约束字体在画面中的行为：

1. Hero 手写字：由图生图承担，追求不等宽、发光边缘和与场景光源融合。
2. 中文模块标题：自然中文字面比例、700 字重、紧凑行高、轻微整块旋转；不再使用 `scaleX/skewX` 强行做窄。
3. 中文正文：以 PingFang SC / Hiragino Sans GB 等自然比例为基础，使用约 700 字重、短行宽和 1.5 左右行高。
4. 英文元信息：DIN/Avenir/Arial Narrow 一类窄体，大写、加字距、字号明显低于中文标题。
5. 日期和进度数字：DIN Condensed/DIN Alternate，高对比字号、斜体和紧行高。

`index(1).html` 的效果更好，关键并不是特殊字体文件，而是它让字级、字重、自然字面、换行和纸面空间共同工作。当前实现因此取消了中文强制横向压缩，并用 `clamp()`、700 字重和整块约 0.4–0.8 度旋转建立层级。

### 10.4 层叠关系必须服从文字安全

- 折纸主标题可以压住后方纯色面板，但面板正文必须通过顶部 padding 让开。
- 副标题纸条下方若紧接带文字卡片，两者实际边界必须至少相隔 12px；禁止依赖肉眼猜测。
- 当前任务模块使用正常文档流承接黄色状态卡，移除了会让副标题压入正文的 `margin-bottom: -29px`。
- 主标题与黄色状态标签使用同一左侧视觉轴；副标题纸条单独向右错位，复现 benchmark 的层级而不是产生随机偏移。
- 所有固定高度模块都要检查 `scrollHeight/clientHeight`，所有相邻文字层要检查 `getBoundingClientRect()` 是否相交。

### 10.5 细节不是散落装饰，而是内容语法

本轮补回的 benchmark 细节包括弧形括号、纸飞机、双角胶带、细框外伸线和关键词高亮。使用规则：

- 弧形括号只包围活动核心说明。
- 纸飞机只承担阅读方向提示，不能反复铺满页面。
- 胶带必须连接真实纸面或框线的角，不悬空。
- 外伸框线用于强化开放式礼物清单边界。
- 黄色/蓝色高亮只落在日期、任务动作、奖励与状态关键词上。
- 不允许出现无文案的空纸条；每个纸片都必须有信息职责。

### 10.6 Hero 与正文的衔接

Hero 只负责主 KV，不耦合活动规则。蒙版只能在底部短距离收口，不能覆盖大段插画、压暗图生图标题。正文延续同一深蓝底色、颗粒和点阵，通过短渐变自然接入，而不是使用突兀分割线或突然切换成另一套浅色页面。

### 10.7 后续每轮的验收顺序

1. 对照 benchmark 检查模块总体比例和阅读节奏。
2. 检查字体角色、字级差、倾斜方向、起始轴与换行。
3. 检查所有相邻文字矩形是否相交，并验证至少 12px 安全间距。
4. 检查纸张层叠是否只覆盖背景，不覆盖正文。
5. 检查 benchmark 的关键细节是否被业务化使用，而非机械堆叠。
6. 在浏览器读取真实 DOM 坐标和 overflow，再运行 `npm run lint` 与 `npm run build`。

## 11. 2026-09-07 家居焕新 H5 反推验证：可迁移到最终 skill 的流程

本轮 `/h5-reference-lab` 验证了同一套方法如何迁移到完全不同的 benchmark：从深蓝音乐拼贴切换到暖黄家居投稿 H5，先稳定视觉反推，再写页面，不把旧页面代码当作模板。最终规范记录在 `docs/h5-home-guide-benchmark-system.md`。

### 11.1 先做 Reference Anatomy，再做业务映射

反推顺序必须固定为：

1. 识别 Hero 的真实材质、主体边界和是否透明，而不是先决定用背景图还是 CSS。
2. 拆解模块标题、卡片底图、外边框、按钮、内容流和页尾过渡的视觉职责。
3. 为每种形态建立可执行参数：比例、缺口/折面、描边层数、纹理位置、阴影、内容安全区、重叠关系和纵向节奏。
4. 先写 Brand Kit / Typography Morphology / Asset Contract，再把业务文案放进去。
5. 最后实现组件与交互，并用浏览器截图验证整页比例。

不能把“暖黄、宋体、圆角卡片”当作完整结论；必须能说明每个装饰、每个边框和每个文字层在页面中承担什么作用。

### 11.2 已验证有效的 Asset Contract

- Hero 如果 benchmark 是透明物件叠在页面底色上，必须使用真实 alpha-cutout 资产；`mix-blend-mode`、长蒙版、白底容器和伪棋盘格都不能代替透明度。
- 图生图先负责主体材质和构图，业务标题、副标题、日期、规则和按钮保留给 HTML；若 Hero 艺术字确实与插画融合，则文字可以随图生图固化，但仍保留无障碍 HTML 标题，禁止再次叠加第二套视觉字。
- 本轮生成工具输出的棋盘格并不等于透明 PNG；必须通过 `hasAlpha` 检查，并在必要时做确定性的背景抠除和边缘清理。
- 代码原生 SVG 适合承载可伸缩的纸张轮廓、双层边框、标题装饰线、折面票签和织纹；不适合假造复杂 3D 家具或照片质感。

### 11.3 已验证有效的 Component Family

共享的是视觉 DNA，不是同一份通用 Card：

- `DecoratedTitle`：左侧连续渐隐山形 + 中央标题 + 右侧多条细线与回环，卡内标题和章节标题只调整尺寸与留白。
- `OrnatePanel`：每种业务卡拥有独立 SVG 轮廓；介绍牌匾、拱顶投稿卡、奖励牌匾不能复用同一圆角矩形。
- `DirectionTab`：低矮八边折面票签，选中态有暖黄纸面、左侧折面和山形水印，未选中态主动降对比。
- `ContentFeed`：图片、播放标记、标题、作者三层保留完整纵向信息密度，不压成后台列表。
- `SubmitCTA`：只在页面末尾使用暖橙胶囊，不与票签或纸张轮廓混用。

### 11.4 长 H5 的背景与节奏规则

- 页面背景要作为一条纵向色带被反推：本轮是“首屏暖黄 → 信息区暖白 → CTA/合作伙伴区淡黄”，靠长距离渐变和局部光晕过渡，不靠分割线。
- 设计基准 430px 时，不以“首屏看完”为目标；完整链路保留约 2100–2300px，Hero/介绍、投稿/奖励、内容流/CTA/页尾分别承担不同的纵向比例。
- 参考图中的底部内容流不能被压缩；图片、正文、作者和 CTA 都是页面节奏的一部分。
- 页面验收必须同时看局部截图和整页长度，避免首屏好看但下半页塌缩或留下无业务空白。

### 11.5 最终 image-to-H5 reverse skill 应固化的检查表

每轮生成都按以下顺序输出中间结论：

1. Reference Anatomy：页面分段、视觉锚点、层叠关系、背景连续性。
2. Brand Kit：色彩角色、材质、边框、阴影、装饰语法。
3. Typography Morphology：字形骨架、宽高比、倾斜来源、字号倍率、文字所有权。
4. Asset Contract：哪些由图生图、哪些由 SVG、哪些由 HTML，透明度和裁切规则是什么。
5. Component Family：可复用 DNA 与必须保持差异的模块。
6. Layout Contract：设计基准宽度、内容安全区、纵向长度、重叠允许范围。
7. Implementation：先独立新页面/新文件，再接入路由，不在旧页面上叠加修补。
8. Visual QA：检查 alpha、字体形态、文字相交、横向 overflow、整页背景过渡、按钮状态与页面长度。

如果视觉不相似，诊断优先级固定为：资产边界 → 字体形态 → 模块结构 → 间距/比例 → 装饰细节；不能一开始就继续加贴纸、阴影或随机调整颜色。
