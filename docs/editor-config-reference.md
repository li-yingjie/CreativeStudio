## 一、总览

### 1.1 产物类型如何路由到编辑器

画布里选中一个产物后，右侧出现哪个编辑器，由产物的运行形态字段决定。产物运行形态必须是数据里的**显式字段**（建议字段名 runtime），不能靠名称前缀推断——当前 Demo 是用"H5 ·""Lynx ·"这类标签前缀的正则来推断类型（DocumentedActivityWorkspace.tsx），打错一个前缀就会分流到错误的编辑器，属于要修正的实现方式。

运行形态枚举（runtime，5 个值）：

1. **h5**：H5 页面 → H5 页面编辑器
2. **lynx**：Lynx 页面 → Lynx 页面编辑器
3. **native**：原生页/原生化卡片 → 一期只读预览，不提供编辑器（magicx 侧对应 TTML 阿拉丁卡体系，与 H5 组件不可混用）
4. **image**：分层图片 → 分层图片编辑器
5. **document**：Markdown 文档 → 文档编辑器（独立，不在本文范围）

玩法配置走独立的表单编辑器（按玩法实例切换），也不在本文范围；页面编辑器里只出现"玩法绑定"引用，见第五章。

### 1.2 统一对象五层在三类编辑器里的对应物

1. **产物层**：有独立版本、画布尺寸、来源和交付状态的实体。
   - H5 编辑器里是 H5 页面实例；Lynx 编辑器里是 Lynx 页面实例；分层图片编辑器里是图片文档。
2. **结构层**：决定组织、顺序、显隐与约束。
   - 页面类是页面区域和布局容器；图片类是图层组。
3. **元素层**：用户主要精确编辑的对象。
   - 页面类是组件、文案、媒体、动作；图片类是文字图层、栅格图层、矢量图层、形状图层。
4. **绑定层**：连接运行或交付规则。
   - 页面类是路由、事件、玩法实例、数据状态；图片类是模板槽位、素材引用、品牌规则。
5. **选区层**：生成式修改的显式作用范围。
   - 页面类是批注锚点；图片类是画笔矩形选区与保护区。

### 1.3 三类编辑器共用的公共机制

以下机制在三个编辑器里语义一致，只实现一份：

1. **选择模型**：画布与对象树双向选中并同步高亮；Esc 清空选择；点击空白清空选择但不关闭编辑器；只读对象可选中但置灰。（需求已定；H5 画布部分 Demo 已实现，H5CanvasStore.ts）
2. **撤销与重做**：历史栈上限 50 步；连续拖拽合并为一条记录（按下时打快照、抬起时统一提交）；恢复模板版本是独立动作。（Demo 已实现，H5CanvasStore.ts 与 HotTopicBannerWorkspace.tsx 各有一份，机制相同，应抽成公共实现）
3. **修改协议**：人工修改、Chat 修改、Comment 修改、画笔修改统一归一为 Patch。每条 Patch 至少记录：目标产物、目标对象、字段路径、旧值、新值、操作者、基础版本号、来源。操作枚举 3 个值：replace、add、remove；操作者枚举 3 个值：agent（智能体）、operator（运营人工）、import（导入）。基础版本号过期的整批拒绝。（需求已定，product-architecture.md 的 ActivityPatch 定义）
4. **人工接管**：人工改过的字段标记为运营所有；后续 Agent 修改默认跳过并展示差异，不静默覆盖；对含人工接管子字段的父对象做替换或删除，等同触碰人工字段。（需求已定）
5. **权限四级**（对象级通用枚举）：
   - **可编辑**：可修改声明字段，可被 AI Patch 命中。
   - **受约束**：只能在模板允许范围内修改，例如字号阶梯内调整、安全区内移动。
   - **受保护**：可查看来源和规格，不渲染修改与删除按钮。
   - **外部参考**：只读，不可编译进正式交付。
   （需求已定；Demo 目前只有一个布尔锁定字段，四级需要新建）
6. **数据展示状态枚举**（页面类产物预览可切换的状态，6 个值）：loading（加载中）、empty（空数据）、error（失败）、not-logged-in（未登录）、not-eligible（资格不足）、completed（已完成）。（需求已定；Demo 未实现状态切换）
7. **校验时机**：保存前执行字段、权限、布局、端能力、引用完整性校验；校验结果就地定位到字段，不做常驻检查大盘；已发布版本只读，修改必须派生新草稿。（需求已定）

## 二、H5 页面编辑器

### 2.1 对象层级树

- H5 页面实例（产物）
  - 页面区域（结构，按语义分区，纵向排列）
    - 布局容器（结构，可嵌套一层）
      - 业务组件（元素，登记制）
        - 内容元素（元素，组件内的文字/媒体槽位）
  - 交互动作（绑定，挂在组件或元素上）
  - 玩法绑定（绑定，挂在页面或组件上，引用玩法实例）
  - 数据状态（绑定，页面级展示状态）
  - 批注锚点（选区，画布 AI 修改的作用对象）

### 2.2 枚举定义

1. **页面区域枚举（sectionRole，5 个值）**：
   - hero（头图区）、navigation（导航区）、content（内容区）、task（任务与回流区）、footer（页尾区）。
   - 状态：需求已定（wiki 与规格文档均为这 5 类）；Demo 已实现其中 4 个（DocumentedPageEditorState.ts 的 PageEditorElementId 只有 hero、navigation、content、footer，缺任务与回流区，需要补）。
   - magicx 对照：magicx 的页面模型是"页面下的楼层"（页面直接子节点即楼层，头图必须是第一楼层且不可删，楼层总数不超过 10 个）。楼层约束可直接搬：**头图区必选且固定第一位，区域总数上限 10**。（参考 magicx，operate-page-schema 约束）
2. **布局容器枚举（containerType，5 个值）**：
   - vertical-flow（纵向流）、horizontal-list（横向列表）、grid（栅格）、positioned（定位容器，容器内子元素才允许自由坐标摆放）、overlay（弹层容器）。
   - 状态：需求已定（5 类名称）；字段细节待定义。magicx 对照：卡片容器、组容器、Tab 容器、轮播容器、滑动容器、条件场景容器，其中"组容器禁止包裹按钮和玩法组件"这类约束规则可搬（参考 magicx，component-constraints 规则表）。
3. **业务组件枚举**：登记制，不是封闭枚举——组件从组件库登记进来，每个组件自带"开放属性 schema"。一期建议直接采用 magicx 的 H5 组件能力清单作为登记基准，类目如下（参考 magicx，componentCapabilities 清单，各类目下均为完整列举）：
   - 容器类：卡片容器、组容器、Tab 容器、轮播容器、滑动容器、条件场景容器。
   - 图文展示类：图片、头图、文本、跑马灯、活动说明、POI 内容卡片。
   - 按钮类：按钮、提交按钮、抖音关注按钮、抖音预约直播按钮、计时器。
   - 媒体类：抖音直播卡片、抖音视频、灵感视频、日历、节目单。
   - 列表类：直播间列表、抖音用户列表、抖音视频列表、话题视频列表、团购交易列表。
   - 表单类：单选、多选、单行输入框、多行输入框、图片上传（不支持邀请码校验与归因）。
   - 玩法类：任务（通用/列表/关注/分享/兑换/单一/多阶段/聚合/双层累计）、抽奖（通用/九宫格/转盘）、榜单（单层非晋级/单层晋级/双层晋级/小时赛道）、签到、报名、组队、集卡、投票、隔空 PK、许愿歌单、积分进度条、弹幕、邀请码、抖音搜索（页面唯一且必须放最后一层）。
   - 投放端限制同样要搬：非直播投放端禁止一切直播场景组件（前缀 webcast 的组件全部禁用），这是组件级权限锁定的现成实现。（参考 magicx，productUIdComponentRules）
4. **内容元素枚举（elementKind，7 个值）**：
   - text（文本）、button（按钮）、image（图片）、video（视频）、icon（图标）、tag（标签）、card（卡片条目）。
   - 状态：需求已定 6 类（标题/副标题归入 text）；Demo 已实现 4 类（H5LayerEditPanel.tsx 的 H5ElementKind：text、button、image、card），video、icon、tag 待补。
5. **交互动作枚举（actionType，8 个值）**：
   - navigate（页面跳转）、anchor（锚点定位）、open-overlay（打开弹层）、close-overlay（关闭弹层）、submit（提交）、share（分享）、back（返回）、refresh（刷新）。
   - 状态：需求已定（名称层面）；字段级待定义，建议每个动作实例包含：动作类型、目标（地址/锚点标识/弹层标识）、埋点开关、失败提示文案。
6. **内容来源枚举（contentSource，4 个值）**：project-input（项目输入）、brand-skill（品牌或 IP 技能产出）、knowledge（知识库）、manual（人工输入）。（需求已定，名称层面）

### 2.3 可配置项（右栏三个分类）

右栏固定三个分类页签：内容、组件、交互。每个分类只展示当前选中对象适用的字段；禁用项必须说明原因。

**分类一：内容**（选中内容元素时）

1. 文本元素：
   - **文案内容（text）**：字符串；多行判定按元素声明；长度上限由组件 schema 声明（Demo 现值可作默认：主标题 20 字、副标题 48 字、按钮文案 12 字，DocumentedPageEditor.tsx）；换行与截断规则校验；安全词校验。（需求已定 + Demo 已实现部分）
   - **字号（fontSize）**：数字，像素；Demo 现值范围 12 至 36、步长 1、默认 20（H5LayerEditPanel.tsx）；正式版应改为读组件主题 Token 的字号阶梯，而不是自由数值。（Demo 已实现，约束方式待定义）
   - **文字颜色（color）**：取值来自主题 Token 色板，不开放任意色值；Demo 现状是 5 个固定色板值。（Demo 已实现，取值来源待定义）
   - **对齐（textAlign）**：枚举 3 个值 left、center、right。（Demo 已实现）
   - **加粗（bold）**：布尔。（Demo 已实现，但当前是面板内部状态没有回写数据层，需接线）
2. 图片/视频元素：
   - **素材引用（assetId 与 src 双字段）**：素材库资产标识 + 静态地址；两种引用方式显式区分（Demo 里夏日冲浪配置已做出这个区分，SummerSurfH5Preview.tsx 的 image 与 imageAssetId，建议全局采用）。（Demo 部分实现）
   - **替代文本（alt）**：字符串。（需求已定，Demo 未实现）
   - **适配方式（fit）**：枚举 3 个值 cover（填充裁切）、contain（完整包含）、fill（拉伸）。（Demo 已实现）
   - **焦点位置（focalPoint）**：横纵百分比，裁切时保住的画面重心。（需求已定，Demo 未实现）
   - **封面（poster）**：仅视频，素材引用。（需求已定，Demo 部分实现）
   - **生成提示词（prompt）**：字符串，仅生成图；配套动作：重新生成、上传替换、裁剪。（Demo 已有字段与按钮，但按钮全部未接线）
3. 卡片条目元素：标题、描述、底图引用、圆角、条目内开关（如展示创作者、展示数值），字段由组件 schema 声明。（Demo 已实现一版，字段应收编进组件 schema 而非硬编码）
4. **内容来源标注（contentSource）**：见枚举 6，只读展示 + 可人工改写触发人工接管。（需求已定）

**分类二：组件**（选中区域、容器或组件时）

1. **结构操作**：显隐（visible，布尔）、锁定（locked，布尔）、复制、删除、同级排序（上移/下移）；开放组件支持移动、复制、显隐、排序，复杂布局仍受模板约束。（需求已定 + H5 画布 Demo 已实现：复制副本强制解锁并偏移 16 像素、层级由数组顺序归一化，H5CanvasStore.ts）
2. **几何字段**（定位容器内的对象才开放）：X、Y、宽、高，数字，像素；宽高最小 16（Demo 现值）；层级顺序通过排序操作调整，不直接编辑数值。（Demo 已实现）
3. **盒模型字段**：内边距、外边距、间距、对齐、排列方向；只暴露组件 schema 声明的受控样式字段，不开放自由 CSS；高级 CSS 只对有权限的专业模式开放。（需求已定；magicx 排布约束可直接搬做校验：组件不得超出页面容器、禁止高度为 0、按钮最大宽 638 像素最小高 80 像素、图片建议最大宽 638 极限 702、相邻文本总间距不超过 12 像素、禁止白字配近白底等。参考 magicx，component-constraints）
4. **组件变体与主题**：变体（组件 schema 声明的枚举）、尺寸档位、主题 Token（圆角、背景、字色从 Token 取值）。（需求已定，待定义具体 Token 集）
5. **预览宽度（deviceWidth）**：数字，范围 360 至 430、步长 10（Demo 现值）；断点内不得横向溢出。（Demo 已实现 + 需求已定）

**分类三：交互**（选中页面、动作或玩法绑定时）

1. **页面路径（route）**：字符串，站内路径格式校验。（Demo 已实现为自由文本，格式校验待补）
2. **外链、锚点、返回目标、分享入口**：动作实例列表，字段见交互动作枚举。（需求已定，Demo 未实现）
3. **玩法绑定**：玩法实例引用（从项目玩法配置选择，不能新建）；页面级参数只有三个：任务开关（taskEnabled，布尔，默认开）、分享开关（shareEnabled，布尔，默认开）、每日上限（dailyLimit，数字，Demo 现值范围 1 至 10 默认 3）。其余玩法字段一律跳转玩法配置表单编辑，页面内不维护第二份。（Demo 已实现 + 需求已定）
4. **数据状态预览**：切换枚举 6 个值预览对应展示态。（需求已定，Demo 未实现）
5. **埋点开关**：点击、曝光，布尔。（Demo 已实现按钮级点击埋点开关）

### 2.4 画布 AI 修改（画布工具栏浮层，不属于右栏）

1. 作用对象三选一：当前页面、选中区域、选中组件；修改前必须展示将修改的对象和字段清单，不允许全页悄悄重做。
2. 修改要求输入自然语言；生成可预览的差异（Patch），确认后应用；人工接管字段默认跳过并列出。
3. 只能修改 schema 开放的字段、顺序和绑定。
（需求已定；Demo 已有基础语义修改，需从右栏移出到浮层）

### 2.5 H5 专属约束

1. 使用组件树与受控样式字段，不开放自由 HTML/CSS。
2. 移动端宽度 360 至 430 像素及约定断点；长页高度由内容自然撑开。
3. 页面画布只展示可操作的浏览器运行态；不提供设计稿切换和设计稿下载入口。
4. 玩法字段写回项目玩法事实源。

### 2.6 Demo 现状与本模型的映射

Demo 当前有两套并行 H5 编辑模型，本文模型是两者的合并收敛：

1. **营销 H5 的楼层坐标模型**（H5CanvasModel.ts：楼层带 X/Y/宽/高/层级的自由摆放）→ 收敛为"定位容器内的对象"能力；语义区块仍是主干结构。它的画布交互（拖拽、快捷键、撤销合并、复制粘贴）整套保留，是目前完成度最高的画布实现。
2. **活动交付物的区块显隐模型**（DocumentedPageEditorState.ts：文案 + 4 个区块开关 + 容器行为）→ 收敛为本模型的"内容分类 + 区域显隐"子集，需补任务与回流区、组件层、动作实例。

## 三、Lynx 页面编辑器

### 3.1 对象层级树

- Lynx 页面实例（产物，由页面标识三元组唯一确定）
  - 端容器（结构，页面外壳：状态栏、标题栏、安全区、滚动容器、端内弹层）
  - 页面区域（结构，与 H5 相同的 5 类语义区块）
    - 业务组件（元素，仅限平台登记的 Lynx 组件、Dux 组件与活动业务组件）
      - 内容元素（元素，组件声明的内容槽位）
  - 端内动作（绑定，Bridge 动作实例）
  - 玩法与数据绑定（绑定，玩法实例、端能力、登录态、服务数据）
  - 状态变体（绑定，端版本/登录/权限/阶段维度的展示变体）

说明：Dux 是抖音端内的标准组件体系，DuxTitleBar 即端内标准标题栏组件；Bridge 指前端页面调用客户端原生能力的桥接通道。

### 3.2 枚举定义

1. **页面标识三元组**：
   - **bundle（资源包名）**：字符串，端内页面的代码包标识。
   - **channel（渠道标识）**：字符串，发布渠道标识。
   - **route（路由）**：字符串，端内打开链接，形如 aweme://lynxview/?channel=某活动&bundle=main。
   - 状态：需求已定（一期允许查看与草稿修改，发布时强校验）；Demo 里 channel 和 bundle 只存在于一份已废弃未引用的旧代码（ActivityDeliverablesWorkspace.tsx），当前接线的编辑器只有一个无校验的自由文本 route，三元组需要正式建模。
2. **标题栏模式（titleBar，3 个值）**：standard（标准）、transparent（透明沉浸）、hidden（隐藏）。（Demo 已实现三值开关）
   - 配套字段（全部待定义，Demo 缺失）：标题文案（字符串）、返回按钮显隐（布尔）、右侧动作区（动作实例列表，如分享）、标题栏背景色与沉浸渐变（Token 取值）。
3. **状态栏前景色（statusBarStyle，2 个值）**：light（浅色文字）、dark（深色文字）。（需求已定，Demo 未实现）
4. **安全区（safeArea）**：顶部适配（布尔）、底部适配（布尔）分开配置。（需求已定"顶部/底部安全区"；Demo 现状只有一个整体布尔，需拆分）
5. **返回策略（backBehavior，3 个值）**：close（关闭容器）、history（返回上一页）、route（跳转指定业务目标）。选择 route 时必须配套 **返回目标（backTarget）**：字符串，端内链接。（Demo 已实现三值枚举，但选 route 后没有目标输入框，是悬空选项，需补字段）
6. **Bridge 动作枚举（bridgeAction，一期 7 个值）**：back（返回）、share（分享）、login（登录）、open-live（打开直播间）、open-topic（打开话题页）、open-item（打开作品）、navigate（端内跳转）。
   - 每个动作实例字段：动作类型、入参（键值对，按动作类型声明）、失败回退（枚举：提示文案 / 降级跳转 / 静默忽略）、最低端版本（字符串，版本号）。
   - 状态：需求已定（名称层面）；Demo 完全没有 Bridge 概念，全部待建。magicx 没有可搬结构（见 3.5）。
7. **状态变体维度（4 个）**：端版本、登录状态、权限状态、活动阶段。每个变体是"维度取值组合 → 展示差异"的映射。（需求已定，Demo 未实现）

### 3.3 可配置项（右栏三个分类）

**分类一：内容**：与 H5 完全一致的文案和媒体槽位字段（见 2.3 分类一），差异只有两条：

1. 每个字段的长度、枚举、本地化约束由端组件的内容 schema 声明，编辑器只渲染 schema。
2. 不允许通过自由 HTML 覆盖端组件结构（H5 专业模式的高级 CSS 通道在 Lynx 不存在）。

**分类二：组件**：

1. 组件只能从已登记的 Lynx/Dux/活动业务组件中选择；开放的修改面为：组件 schema 声明的 props（开放属性）、槽位内容、显隐、同级顺序。（需求已定）
2. 页面区域仍按 5 类语义区块组织（同 2.2 枚举 1）。
3. **端版本兼容**：组件登记信息里带最低端版本；当前预览端版本低于要求时，组件显示禁用原因，不提供无效开关。（需求已定，Demo 未实现）

**分类三：端容器与交互**：

1. 页面标识三元组（见 3.2 枚举 1）：一期可查看、可草稿修改，发布时强校验。
2. 标题栏：模式 + 配套字段（见 3.2 枚举 2）。
3. 状态栏前景色、页面背景（Token 取值）、滚动行为（枚举 2 个值：页面整体滚动、容器内滚动）。（需求已定，滚动行为取值为建议）
4. 安全区顶部/底部开关。
5. 返回策略 + 返回目标。
6. Bridge 动作实例列表。
7. 玩法绑定：与 H5 相同的三个页面级参数（任务开关、分享开关、每日上限），其余跳玩法配置。

### 3.4 与 H5 的共用与差异

1. 共用：编辑器壳、右栏三分类结构、内容字段控件、区域枚举、玩法绑定边界、选择/撤销/Patch 机制。
2. Lynx 专属：页面标识三元组、端容器全部字段（标题栏/状态栏/安全区/返回策略）、Bridge 动作、端版本兼容检查、状态变体。
3. H5 专属：预览宽度与断点、专业模式高级 CSS、浏览器行为检查（后退、刷新恢复）。
4. 发布门禁差异：Lynx 的发布门禁是安全区、标题栏、返回与分享 Bridge、最低端版本四项；端服务未接入时必须显示"待接入"，不能用成功提示冒充。（需求已定）

### 3.5 magicx 参考边界（重要）

magicx 的页面类型枚举里，Lynx 被明确标记为"暂不支持生成"（识别到即建议改 H5），magicx 也没有 Lynx 端容器、Bridge、bundle/channel 的任何 schema。所以：

1. **可以搬**：H5 组件能力清单与排布约束（作为"活动业务组件"登记基准）、组件级投放端禁用策略（做端能力权限的现成模式）。
2. **不能搬、需要新定义**：3.2 的全部端容器与 Bridge 字段。建议直接对接端上 Dux 组件平台与 Lynx 容器的登记数据来定枚举，不要自造。
3. magicx 的 TTML（原生化阿拉丁卡）是第三种体系，组件前缀不同且与 H5 组件不可混用，对应本文的 native 运行形态，一期只读，不要把它和 Lynx 混为一谈。

### 3.6 Demo 现状缺口清单

1. runtime 类型靠标签前缀推断 → 改显式字段。
2. bundle/channel 字段缺失（只在死代码里出现过）。
3. 返回策略的 route 选项没有目标输入框。
4. Bridge 动作、最低端版本、端版本兼容检查完全空白。
5. 标题栏只有三值模式，无标题/动作/背景配置；渲染组件里状态栏是写死的装饰。
6. 安全区只有单布尔。
7. 任务与回流区在区块枚举里缺失。

## 四、分层图片编辑器

### 4.1 对象层级树

- 图片文档（产物）
  - 图层组（结构，显式树，组持有图层引用列表，可整组锁定）
    - 图层（元素，四种类型）
  - 素材槽位（绑定，模板声明的可替换位）
  - 模板引用、风格引用（绑定，锁定精确版本）
  - 画笔选区与保护区（选区）

Demo 里有两套图层模型：AssetLayerManifest.ts（扁平无分组、无校验、无导出）和 LayeredArtworkDocument.ts（分组树、锁定基线校验、画笔选区、PNG 与图层 JSON 导出）。**以后者为唯一基准**，前者应迁移淘汰。后者与 product-architecture.md 的 ImageAssetVersion 定义结构一致。

### 4.2 枚举定义

1. **图层类型（type，4 个值）**：raster（栅格）、text（文字）、vector（矢量）、shape（形状色块）。
   - 冲突说明与收敛建议：架构文档写的是 raster/text/vector/upload，Demo 完整版实现是 raster/text/vector/shape。"upload（上传）"描述的是素材从哪来，不是图层是什么，来源已由 renderer 和文档级 source 字段表达，放进类型枚举是重复建模。建议类型枚举定为上述 4 值，去掉 upload。（待定义，需拍板）
2. **渲染来源（renderer，5 个值）**：image-model（图像模型生成）、raster-art（艺术字栅格）、true-text（真文字排版）、brand-asset（品牌资产）、source-asset（已有素材）。三处定义完全一致，直接定稿。（需求已定 + Demo 已实现）
3. **文档来源（source，4 个值）**：generated（生成）、uploaded（上传）、imported（导入）、derived（派生）。（需求已定，架构文档）
4. **图层组语义（6 个值）**：main-visual（主视觉）、content-info（内容信息）、metrics（指标）、ops-action（运营动作）、logo（品牌标识）、delivery-info（交付信息）。（需求已定；Demo 的 Banner/海报实例分组与此对应）
5. **权限**：沿用公共四级（可编辑/受约束/受保护/外部参考）。默认受保护对象：品牌 Logo、二维码、证据图片、复杂主视觉、未授权 IP。（需求已定；Demo 现状只有布尔锁定，四级待建）
6. **单图与分层的关系**：不设"单图/可分层/已分层"三态。普通单图就是清单里只有一个铺满画布的栅格根图层；"建议分层"只是 Agent 的临时建议字段（keep-flat 或 consider-layering），不是产品状态。（需求已定，架构文档 + Demo 已实现）

### 4.3 可配置项

**文档级**：

1. **画布（canvas）**：宽、高，数字，像素；与模板基线不一致时校验拒绝保存。（Demo 已实现）
2. **模板引用（templateRef）与风格引用（styleBibleRef）**：标识 + 精确版本号，锁版本不自动跟最新。（需求已定）
3. **版本信息**：版本号、扁平图地址、来源枚举、渲染器版本。（需求已定，架构文档 ImageAssetVersion）
4. **交付尺寸组**：原始画布与各派生尺寸、像素密度、色彩空间、文件格式。（需求已定，Demo 未实现派生尺寸）

**图层组级**：

1. 组名、语义枚举值、整组锁定（布尔）、整组显隐、组内顺序。（Demo 已实现数据结构；整组锁定目前只是标注，未做批量禁用，需接线）

**图层级公共字段**（四类图层共有）：

1. **位置与尺寸（x/y/width/height）**：数字，像素；仅模板允许的图层可变换；移动被画布边界钳制；缩放最小宽 24、最小高 18（Demo 现值）。
2. **层级顺序（z）**：只通过上移/下移一层调整，锁定图层不参与交换。（Demo 已实现）
3. **显隐（visible）**：布尔；锁定时禁用。（Demo 已实现）
4. **不透明度（opacity）**：数字，范围 0.1 至 1、步长 0.05、默认 1。（Demo 已实现）
5. **锁定（locked）**：由权限模型派生，编辑器内不提供解锁入口。（Demo 已实现）
6. 一期不开放：任意旋转、混合模式、像素级自由擦除（进专业模式评审）。（需求已定）

**文字图层专属**：

1. **文字内容（text）**：字符串，多行；必填校验（未锁定文字图层不允许空文本，Demo 已实现该校验）。
2. **字体（fontFamily 与 fontRef）**：字体族名 + 字体库引用（标识、版本、族名）三元组，保证交付可追溯。（Demo 有字段无编辑入口，控件待建）
3. **字号（fontSize）**：数字，Demo 现值范围 8 至 180、默认 32；正式版按模板声明的字号阶梯约束。
4. **字重（fontWeight）**：数字档位（400/500/600/700），默认 600。（Demo 有字段无控件）
5. **行高（lineHeight）**：数字倍率，默认 1。（Demo 有字段无控件）
6. **字距（letterSpacing）**：数字，像素，默认 0。（Demo 有字段无控件）
7. **颜色（color）**：色值，默认 #161823；品牌场景应从品牌色 Token 取值。（Demo 已实现自由取色，取值来源待收紧）
8. **对齐（textAlign）**：枚举 3 个值 left、center、right。（Demo 有字段无控件）
9. **换行与容量规则**：由模板声明（如标题 3 至 14 字、副标题不超过 16 字——Demo 对 Banner 已实现该校验，字数按 Unicode 码点计数）。

**栅格/矢量图层专属**：

1. **素材引用（src 与 assetId）**：地址 + 素材库标识双字段；替换来源枚举：素材库选择、本地上传、重新生成。（Demo A 有本地上传替换，Demo B 未做，需统一）
2. **裁切与焦点**：裁切框 + 焦点位置。（需求已定，Demo 未实现）
3. **授权状态**：只读展示，来自素材治理数据。（需求已定）
4. **形状填充（fill）**：仅形状图层，色值。（Demo 有字段无控件）
5. **遮盖块（redactions）**：矩形列表（位置尺寸 + 填充色），用于遮盖底图敏感区，只读不可编辑。（Demo 已实现）

**素材槽位**（模板声明，绑定层）：

1. 槽位角色枚举（7 个值）：ip（IP 形象）、logo（品牌标识）、product（商品）、qrcode（二维码）、background（背景）、foreground（前景）、replaceable（通用可替换）。（需求已定，名称层面）
2. 每个槽位字段：角色、接受的素材类型、固定尺寸、当前绑定资产、授权状态。magicx 的组件素材槽位模型可直接参考：槽位以"组件 + 属性路径"定位，且每类槽位有固定生产尺寸（如通用抽奖 1500×1160，任务列表/话题列表/九宫格/奖品图 1024×1024）。（参考 magicx，comp_assets 类型定义）

### 4.4 画布 AI 生成编辑（轻量入口，不属于属性分类）

1. **入口（3 个）**：智能分层、智能画笔、评论。点击图片卡片直接进入画布，不经过单独预览详情页；图层列表和选择收进右侧编辑栏。（需求已定 + Demo 已实现）
2. **Comment 模式**：点击画面百分比坐标放置编号标记，在右侧输入评论；支持多点评论、待处理计数、解决和重新打开。（Demo 已实现）
3. **画笔选区模型**：自由笔刷路径，路径点为画布 0 至 1 归一化坐标；支持撤销一笔、清除、输入局部修改指令并生成候选。（Demo 已实现 Mock 闭环）
4. **保护区（protectedRegions）**：与图层无关的矩形列表（百分比坐标）；选区与任一保护区相交即阻断生成。（Demo 已实现）
5. **目标图层选取规则**：当前选中图层若开放、可见且与选区相交则用它；否则按层级从上到下取第一个满足条件的开放图层；找不到则阻断并提示"选区内没有可生成式编辑的图层"。（Demo 已实现）
6. **结果处理**：生成结果先作为候选版本，不直接覆盖已保存版本；Demo 会明确标记“局部修改候选已生成，原图层保持不变”。（需求已定 + Demo 已实现 Mock）
7. **对话边界**：项目级自然语言指令只保留在左侧会话；素材库和图片编辑器不再重复渲染底部通用对话框。（需求已定 + Demo 已实现）

### 4.5 校验规则清单（保存、导出、读档三个入口统一执行）

结构校验（Demo 已实现，LayeredArtworkDocument.ts）：

1. 画布尺寸与模板基线一致。
2. 图层标识不重复。
3. 图层宽高大于 0，坐标为有限数。
4. 图层不超出画布边界。
5. 锁定图层逐字段与基线比对，被改写或缺失即拒绝。
6. 图层组引用完整性双向校验（组引用的图层必须存在，图层必须被且仅被一个组引用）。

业务校验（模板声明，Demo 已实现两条实例）：

7. 文字容量：按图层声明的字数区间校验。
8. 必填：未锁定文字图层不允许空文本。

交付规范校验（需求已定，Demo 未实现）：

9. 标题容量、安全区、Logo 规则、二维码可扫性、锐度、透明背景。
10. 扁平成片与图层附属文件同时校验。
11. 多层合成的保护像素做合成前后不变量校验。

### 4.6 导出格式

1. **扁平成片**：PNG/JPG/WebP，原始尺寸逐层合成（文字层自动缩字号适配宽度）。（Demo 已实现 PNG）
2. **图层附属文件（sidecar）**：JSON，字段为：格式版本号、画布尺寸、逐层绝对定位的 HTML 表达、展示用图层树、来源信息（生成模式、文档标识与版本）、完整文档深拷贝（可回读）。（Demo 已实现）
3. **运行时合成对照（参考 magicx）**：magicx 的 compose-image 是同一件事的服务端版本，参数结构可作为"图层 JSON → 线上合成"的对接参考：画布模板宽高必填；基准图地址必填；图片层数组（深色/浅色两套素材地址必填，定位参数 left/right/center 与 top/bottom 按优先级互斥，宽高二选一等比缩放）；文字层数组（内容、字号默认 36、字色默认黑、背景色默认透明）；另有搜索框层与二维码层两个业务专用层。它的深浅色自适应机制（按已绘制区域灰度自动切换素材）要求模板素材成对提供，这一点对分层模板的素材规范有直接影响。

### 4.7 magicx 可直接参考的三块

1. **compose-image 参数结构**：见 4.6。
2. **槽位素材固定尺寸表**：见 4.3 素材槽位。
3. **审核规则数据结构**：magicx 原生化卡的审核规则模型（规则编码、级别 P0/P1/P2、规则类型 vision/interaction/component_config/search_words、作用域 activity/component、作用组件列表、规则说明），可作为分层图片"交付规范校验"的规则登记格式。

## 五、玩法绑定的边界（三类编辑器共用）

1. **玩法类型枚举（5 个值）**：抽奖、集卡、任务、投票、答题。金豆一类的副玩法不是第 6 种类型，是"任务 + 抽奖"规则组合出的轨道实例，编辑器不要为它单开类型。（需求已定，gameplay-configuration.md）
2. **页面编辑器持有的玩法字段只有三类**：玩法实例引用（选择，不新建）、页面级开关（任务开关、分享开关）、页面级参数（每日上限）。
3. **其余一切玩法字段**（概率、保底、卡池、奖品、库存、频控、任务事实等）属于玩法配置表单编辑器，按玩法实例一级切换；页面编辑器里点玩法对象时跳转过去，不内嵌第二份表单。
4. 修改玩法字段的 Patch 写回玩法事实源（GameplayPackage 实例），页面只消费。
