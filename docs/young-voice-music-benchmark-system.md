# Young 声音藏品：音乐企划 benchmark 反推系统

状态：Draft 1 — 在继续整页实现前，先以礼物收集模块验证。

## 0. 反推原则

本文件不把参考图压缩成“深蓝 + 黄色 + 手账风”。反推对象分为六层：Reference Anatomy、Brand Kit、Typography Scale、Module Spec、Key Visual Lock / Asset Contract、Evaluation Matrix。

## 1. Reference Anatomy

### 1.1 源图观察

- 头图裁图尺寸：582 × 1014，纵横比约 1.74。
- 内容模块裁图尺寸：318 × 672，纵横比约 2.11。
- 页面不是等高 section 堆叠，而是连续深蓝画布中的不同信息团块。
- 首屏约前 55% 用于情绪场景，标题占中上部；道具沿左右和下部构成视觉框架。
- 正文每屏通常只有一个主标题、一个重点便利贴和一组内容项。

### 1.2 页面节奏

1. 情绪场景：二维夜间音乐房间。
2. 活动定位：倾斜白色标题纸 + 两至三行摘要。
3. 重点规则：黄色便利贴，黑字或深蓝字。
4. 业务内容：同一深蓝表面上的图片、标签和数值，不全部装进白卡。
5. 转化动作：黄色胶囊 CTA。
6. 下一模块通过标题或内容露出自然承接，不用明显分割线。

### 1.3 构图比例（映射至 430px 页面）

- 页面安全边距：20–24px。
- 主内容宽：382–390px。
- 标题纸条宽：260–350px，高 42–62px，旋转 ±1–3°。
- 黄色规则便利贴宽：300–350px，内容高度自适应。
- 同层内容项之间：14–22px；段落之间：24–36px。
- 单屏视觉锚点不超过两个：通常是标题 + 黄色重点区，或人物/物件 + 内容列表。

## 2. Brand Kit

### 2.1 世界观

关键词：深夜音乐客厅、R&B、私人电台、唱片收藏、年轻创作者、轻松但专业。

### 2.2 色彩角色

|---|---:|---|

### 2.3 材质与母题

- 二维动漫背景插画。
- 便利贴、裁纸、胶带、票根和照片纸。

## 3. Typography Morphology Contract

字体反推不能停留在“手写体 / 黑体 / 数字体”标签，而要同时记录五个形态维度：

1. `skeleton`：笔画骨架是手写、几何黑、窄体还是常规正文。
2. `aspect`：字面的宽高比，是否需要 `scaleX` 压缩。
3. `axis`：倾斜来自字体本身、`font-style`，还是整体 `skewX`；禁止三者无区别叠加。
4. `ink`：实心、描边、错版阴影、霓虹发光分别由谁负责。
5. `rhythm`：字号、行高、字距与相邻角色的倍率关系，而不是孤立像素值。

本 benchmark 的字体不是一个全局字体，而是四套互不替代的字形角色：

| Role | 骨架与重心 | 形态参数 | 实际字体栈 | 禁止替代 |
|---|---|---|---|---|
| `hero-hand` | 不等宽手写骨架，中轴轻微摆动，重心居中 | 三行错位；单字倾角不同；白色线芯 + 蓝色光晕与环境反光 | 图生图写入 Hero KV；HTML 仅保留无障碍标题 | 楷体、宋体、统一粗黑、重复叠加 HTML 视觉字 |
| `paper-display` | 自然字面的粗黑/窄体混排，低重心 | `clamp(25px, 6.8vw, 29px) / .96`；整块 `rotate(-.8deg)`；不压缩中文 | `Arial Narrow -> PingFang SC -> Hiragino Sans GB` | 中文 `scaleX/skewX` 强变形、负字距挤压笔画 |
| `body-copy` | 中性黑体，开口清晰，字面不倾斜 | `clamp(11.5px, 3.25vw, 13.5px) / 1.58`；正文统一 700；不压缩 | `PingFang SC -> Hiragino Sans GB -> Microsoft YaHei` | 微型正文、手写正文、低对比细字 |
| `meta-number` | 英文窄体、数字高瘦、基线稳定 | 标签 `7–10px`，数字 `21–48px`；`skewX(-8deg)`；小标签增加 `.12em–.16em` 字距 | `DIN Condensed -> Avenir Next Condensed -> Arial Narrow` | 中文字体模拟数字、等宽代码字体 |

角色倍率：正文为 `1×`，业务项标题约 `1.65×`，模块标题约 `2.25×`，Hero 中文约 `4.6×`，关键数字约 `3.4×–4.2×`。页面验收时需要同时检查字形与倍率，不能只检查 `font-family`。

### 3.1 Typography Scale

| Role | 字体形态 | CSS 候选 | 430px 字号 | 字重 | 行高 | 字距 | Ownership |
|---|---|---|---:|---:|---:|---:|---|
| Hero art title | 不等宽手写、发光、行宽不同 | 图生图标题；HTML fallback 为 Hannotate SC / LingWai SC | 视觉等效 48–55 | 图像固化 | .84–.92 | 不规则逐字节奏 | theme asset + accessible page text |
| Module title | 自然高黑、整块轻旋转、低重心 | Arial Narrow / PingFang SC / Hiragino Sans GB | 25–29 | 700 | .96–1.0 | `-.012em–0` | page text |
| Sticky title | 粗黑短句、轻微倾斜 | PingFang SC / Hiragino Sans GB | 17–20 | 700 | 1.0–1.08 | `0–.01em` | page text |
| Item title | 自然字面粗黑，只允许整块轻旋转 | Arial Narrow / PingFang SC | 15–19 | 700 | 1.0–1.05 | `0` | page text |
| Body | 清晰粗黑、短行宽、高信息密度 | PingFang SC / Hiragino Sans GB | 11.5–13.5 | 700 | 1.50–1.62 | `0` | page text |
| Meta label | 窄体全大写 | Arial Narrow / Roboto Condensed | 7–9 | 800–900 | 1.1 | `.12em–.18em` | page text |
| Date / count | 窄体数字 | DIN Condensed / DIN Alternate / Arial Narrow | 18–42 | 700–900 | .9–1.0 | `-.02em` | page text |
| CTA | 粗黑、单行 | Heiti SC / STHeiti | 12–15 | 800–900 | 1.2 | `0` | page text |

约束：不允许通过一个全局字体覆盖全部角色；每个角色必须同时定义字号、行高、字距和归属。手写体只用于 Hero 艺术字或极少量注释，不用于业务名称和正文。Hero 若采用图生图，必须同时保留语义化 `h1`、禁止再叠加视觉标题，并把准确文案、可读安全区和不可变构图写入 Asset Contract。内容区允许浏览器为 PingFang 合成轻微斜体，但中文禁止 `scaleX` 和大角度 `skewX`；海报感由 700 字重、响应式倍率、整块微旋转和纸张遮挡共同完成。

## 4. Module System

### 4.1 `GiftCollectionModule`（本轮母板）

业务目标：让主播在 5 秒内理解“三件礼物同权、各收一件、与唱歌任务并行”。

内容顺序：

1. 倾斜白纸标题：`01 三件声音藏品`。
2. 黄色规则便利贴：一句玩法标题 + 两行解释。
3. 三件礼物在同一深蓝 surface 上纵向排列，不使用三张独立商品卡。
4. 每项包含透明礼物、英文编号、中文名、价格、状态。
5. 浅蓝手绘线连接三项，仅表达同组关系，不形成步骤箭头。
6. 底部蓝色进度贴：`2/3，还差一丈红`。

### 4.2 后续模块

- `VoiceDensityModule`：三张票据型任务纸条 + 大数字浓度，不能复用礼物列表构图。
- `ArchiveModule`：收藏册/唱片架式状态陈列，不能复用黄色规则便利贴作为主体。
- `PartyInvitationModule`：单张邀请海报 + 资格说明 + CTA，视觉锚点应转向 09.03。

## 5. Component Family

共享 DNA 不等于共享模板。

| Family | 共享规则 | 可变化内容 |
|---|---|---|
| Paper heading | 米白纸、蓝色错版阴影、轻微旋转 | 宽度、编号位置、标题行数 |
| Sticky note | 单色纸面、胶带最多一处、无圆角 | 黄色/蓝色、文字密度、倾斜方向 |
| Item row | 同一父 surface、图片 + 文案 + 数值 | 图片比例、状态表达、左右方向 |
| Ticket task | 缺口/票根边缘、进度条 | 任务长度、数据单位、完成态 |
| CTA | 黄色、高对比、粗字 | 胶囊/折角纸条、文案长度 |

禁止把同一个 `clip-path + shadow + tape` 复制到所有模块。

## 6. Key Visual Lock

必须保真的对象：

- Hero：二维动漫夜间音乐房间及其道具关系。
- Hero 艺术标题：手写发光、三行错落、与窗景绑定。
- 模块标题纸：米白纸条与蓝色错版阴影。
- 黄色规则便利贴：页面最主要的规则强调形式。
- 深蓝 same-surface 内容组织：业务项不全部卡片化。
- 黄色 CTA：每个长段落最多一个。

不得被普通化为：标准白卡、圆角列表、导航栏、玻璃面板、等宽后台表格。

## 8. 母板验收矩阵

每项 0–2 分；低于 12/16 不得推广到全页。

| 项目 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 业务关系 | 被读成步骤 | 需要解释才能理解 | 一眼看出三项平行 |
| benchmark 构图 | 标准卡片列表 | 有便利贴但结构仍 UI 化 | 标题纸 + 重点贴 + same-surface 内容 |
| 字体层级 | 全部同字形 | 有字号差 | 手写/高黑/正文/窄体数字角色明确 |
| 资产边界 | 图文互压 | 偶有安全区问题 | 图片与页面文字职责清楚 |
| 组件家族 | 每块完全不同 | 全部复制同模板 | DNA 一致、构图有差异 |
| 视觉节奏 | 信息平均分布 | 有局部重点 | 每屏 1–2 个明确锚点 |
| 响应布局 | 拉伸或绝对漂移 | 单设备可用 | 内容撑高且窄屏无溢出 |
| 转化路径 | CTA 像工具栏 | CTA 可见 | CTA 与业务结论紧密绑定 |
